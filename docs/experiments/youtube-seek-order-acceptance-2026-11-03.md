# Live-проверка natural-seek-order — 2026-11-03

Основные сценарии новой логики перемотки подтверждены на настоящем YouTube. В двух обычных профилях Chrome с облачным Firebase проверены удержание, серия нажатий, клик и drag: **5 общих команд, revision 1 → 6, правильные авторы, без эха**. Отдельный live-тест с Firebase Emulator Suite подтвердил защиту удержания/drag от чужой перемотки и применение последнего завершённого жеста. Дальний seek в автоматизированном Chromium остаётся ограничением среды: контроль без расширения и Firebase также не смог загрузить эту позицию.

## Обычный Chrome и облако

- Исходники `73add92cfb6c0928ad2deda556aa3c58983c165f`; свежая сборка на Node **24.19.0**, WXT 0.21.5. Продуктовый код не менялся. QA-наблюдатель дополнен записью trusted keyup/pointerup и blur; разрешения и playback API не расширялись.
- Два независимых профиля **Watch Together QA A/B**, Chrome 156 на одном Mac, ролик `aqz-KE-bpKQ`. Anonymous Auth и RTDB `example-qa`, `europe-west1`; разные UID подтверждены по SHA-256. Использованы ранее опубликованные Rules с actionAt/sampledAt, нового деплоя не было.
- Ввод через native Computer Use, без управления браузером через Playwright/CDP. Сеть не менялась; тип подключения, география и VPN не установлены.
- Media-наблюдатель читает HTMLMediaElement и trusted события. Два status-документа читают существующий status API; ключи комнат, UID и Auth-токены не сохраняются.

Обе status-истории содержат все revision 1–6, одинаковый playback, противоположный ownActor, два участника и ноль ошибок. Серии не создают промежуточных общих записей; итоговое действие не теряется. Оба реальных плеера завершили запись готовыми, на паузе, со скоростью 1× и позицией **461,231344 с**. Все пять команд имеют ожидаемого автора; лишних revision после последнего действия нет.

Это функциональная проверка, не новый замер p95 или расхождения ровно через 3 с. Media B записывалось после действий A; обе status-истории покрывают все команды. Перекрытые media-окна имеют пропуски опроса, непрерывное наблюдение с шагом 10 мс не заявляется. Native-удержания не породили OS auto-repeat; автоповтор проверен отдельно ниже. Переключение обычных окон вызывает blur и отменяет жест, поэтому одновременное управление проверялось в отдельных тестовых браузерах.

## Конфликты на настоящем YouTube

Chromium **156.0.8078.4**, headless, два независимых профиля, Firebase Emulator Suite с продуктовыми Rules. Это настоящий YouTube с локальным backend; результаты не смешиваются с облачной выборкой.

- `youtube-matrix.spec.ts`, «более позднее действие побеждает из одной revision»: **passed**, 31,4 с. Команды обоих участников удержаны на исходящем WebSocket до формирования из одной базы; после доставки побеждает более поздняя команда гостя, плееры сходятся, повтора нет. Этот тест не задаёт обратный порядок доставки; такая проверка остаётся в ранее пройденном стендовом `seek-order.spec.ts`.
- Новый `youtube-seek-order.spec.ts`: **passed**, 33,1 с. Пока B удерживает ArrowRight, включая паузу 500 мс и repeat-keydown, A публикует seek на 15 с; B остаётся на своих 25 с. После keyup revision становится 2, оба плеера — на 25 с. Во время drag B чужой seek A на 30 с также не прерывает жест; pointerup публикует revision 4, оба плеера сходятся на 37,374227 с. Автор обеих итоговых команд — B; через дополнительные 700 мс playback не меняется.

Воспроизведение после `npm run build:transport`:

```sh
YOUTUBE_TRANSPORT_REAL=1 node scripts/firebase.mjs emulators:exec --only auth,database,hosting --project demo-watch-together 'node_modules/.bin/playwright test --config playwright.transport.config.ts youtube-seek-order.spec.ts youtube-matrix.spec.ts --grep "удержание и drag|более позднее действие"'
```

## Неуспешные попытки и контроль

Первый вариант live drag шёл от 12% к 18% ползунка, примерно на 114 с. После отпускания revision осталась 3 вместо 4. Повтор с диагностикой воспроизвёл `currentTime=114,162694`, `readyState=1`, `seeking=true`, без рекламы: media не закончило seek, подтверждённый intent ещё не возник. Обе попытки неуспешны и сохранены. Короткий вариант от 4% к 6% прошёл; в обычном Chrome облачный drag на 461 с также прошёл.

Контроль `YOUTUBE_PROBE_POSITION=114 node scripts/youtube-delivery.mjs` в том же Chromium **без расширения и Firebase** вернул exit 1: за 30 с плеер не достиг `readyState >= 3`, затем сбросился на 0 с / `readyState=0` с сообщением «Something went wrong». Сбой воспроизводится вне расширения. Его конкретная причина и различие обычного Chrome/автоматизированного Chromium не установлены. Дальний live seek в автоматизированном режиме не объявляется проверенным.

Все три попытки нового теста, успешный конфликтный тест и полный контроль без расширения сохранены в [live-данных](youtube-seek-order-live-2026-11-03.json). Первоначальный отказ запуска эмуляторов внутри sandbox (EPERM на портах) устранён запуском с нужным доступом и не относится к результатам YouTube.
