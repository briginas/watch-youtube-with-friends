# Приёмка прототипа в обычном Chrome — 2026-11-03

Технический прототип принят в согласованном объёме: **48 команд, 31 пригодный замер, p95 227,90 мс, максимальное расхождение позиции через 3 с — 0,17791 с**. Все 48 команд имеют правильного автора и ровно одну revision, без обратной рассылки. ADR-0002/0003 приняты для прототипа; естественная реклама остаётся отложенной пользователем. Это завершение технического эксперимента, а не всего MVP.

## Условия и наблюдение

- Установленный Google Chrome **156.0.8078.74**, macOS arm64, два независимых профиля Watch Together QA A/B на одном Mac. Сеть и VPN не менялись; тип доступа, география и наличие VPN неизвестны.
- Настоящий YouTube, ролик `aqz-KE-bpKQ`; облачные Anonymous Auth и RTDB проекта `example-qa`, регион RTDB `europe-west1`. Разные UID подтверждены сравнением SHA-256, сами UID не записаны.
- Расширение из `.output/cloud/chrome-mv3`, локальные изменения поверх commit `7fc1190`. Хеши загруженных файлов и исходника адаптера записаны в итоговом JSON.
- Клавиши вводились через native Computer Use. Playwright, CDP и DevTools не управляли страницами и не снимали данные этих прогонов. Тестовые наблюдатели добавлены только в QA-копию сборки; продуктовых API и разрешений не добавлено.
- `tests/cloud/native-media.js` читает фактический HTMLMediaElement каждые 10 мс, trusted keydown и следующие media events. `tests/cloud/native-status.js` читает существующий status API каждые 100 мс: revision, автора относительно своего UID, готовность соединения и участников. Наблюдатели не посылают команды playback.
- Оба плеера и два status-документа открыты в четырёх отдельных видимых окнах. Фоновые вкладки Chrome могут замораживаться; первая попытка ниже показала, почему их нельзя использовать для подтверждения каждой revision.

Время начала — capture trusted keydown. Конец применения — совпадение состояния, скорости и прогнозируемой позиции получателя с источником в течение 100 мс. Использованы общие функции `tests/cloud/measurement.ts`; допуск позиции 0,5 с, разрыв снимков более 100 мс прерывает устойчивое применение. Поиск применения ограничен текущей командой (`input + 3100ms`), последующая команда не может исправить отсутствующий результат задним числом.

Снимки позиции берутся не раньше `input + 3000ms`, с задержкой не более 50 мс, и приводятся к общему времени. При рекламе или `readyState < 3` в первые 3 с либо неготовом плеере на снимке команда исключается из стабильной выборки, но остаётся в отчёте. Все пригодные команды обязаны иметь измеренное применение. p95 — ближайший ранг `ceil(0.95*N)`. Между командами выдерживалось более 3,1 с, обычно ожидание 3,5 с плюс время UI.

| Проверка | Первая попытка | Итоговая попытка |

| Команды / пригодные | 32 / 22 | **48 / 31** |
| Исключены | 10, buffering | 17, buffering |
| Пригодные с применением | 22 | **31** |
| p95 | 343,10 мс | **227,90 мс** |

| Revision | 1 → 33 | **33 → 81** |
| Полная история авторства, без эха | Нет: status-вкладки замораживались | **Да, все 48** |
| Совпадение play/pause/rate через 3 с | Не подтверждено по всей истории | **Да, все 48** |
| Ошибки status API | 0 | 0 |
| Итог | Недостаточно данных, не приёмка | **Критерии выполнены** |

Попытки не объединены. В итоговой выполнены шесть серий по восемь действий, инициаторы B/A/B/A/B/A, по 24 команды от каждого. Серия: Space, Shift+Period, ArrowRight, Space, ArrowLeft, Shift+Comma, Space, Space. При русской раскладке получены trusted `key=Ю/Б`, `code=Period/Comma`; скорость синхронизировалась в обе стороны. Клавиши и все исключения сохранены по каждой команде. Обе стороны завершили на паузе, позиции 530,6 с (8:50), скорости 1×, с двумя участниками. Это достигнутая позиция с перемотками и изменением скорости, а не длительность непрерывного просмотра.

Сброс около 59,916 с в этих двух обычных запусках не повторился. Отдельный минимальный контроль Chromium без расширения/Firebase через Playwright снова воспроизвёл сброс; его отчёт включён в [данные клавиатурной регрессии](youtube-keyboard-2026-11-03.json). Механизм различия обычного и автоматизированного запуска не установлен. Автоматизированный длинный cloud E2E остаётся неуспешным в этой среде; его результат не заменён и не объявлен успешным.

## Исправление клавиатуры и проверки

Адаптер распознавал скорость только по `event.key` `<`/`>`. Нативный YouTube также обрабатывает физические Shift+Period/Comma при русской раскладке. Теперь эти `event.code` разрешают ожидание ratechange. Без фактического media-события, с Ctrl/Alt/Meta, из текстового поля или от синтетического ввода общая команда не создаётся.

Регрессия до исправления воспроизвела локальную скорость 1,5× без intent. После исправления: **19 local player passed**, **1 live rate passed**, **2 sync passed** (стенд и настоящий YouTube). Live sync прошёл revision 0 → 17, включая русские клавиши у обоих участников и управление гостя после выхода создателя. Английские клавиши и отсутствие эха также проверены. Исходные наблюдения — [youtube-keyboard-2026-11-03.json](youtube-keyboard-2026-11-03.json).

Exit 0 означает достаточную выборку, соблюдение обеих метрик, разные UID, правильное авторство всех команд, отсутствие лишних revision, совпадение состояний и отсутствие ошибок status. Пересчёт первой попытки обязан вернуть exit 1. Скрипт проверяется пятью unit-тестами, включая замороженный status, отсутствующее применение, поздние снимки и лишнюю финальную revision.

## Границы решения

Измерен облачный RTDB и настоящий YouTube для двух профилей одного компьютера и общего маршрута. Это не подтверждает задержки между странами или независимыми сетями. Buffering исключён из численных целей, его локальность и восстановление проверены отдельно. Естественная реклама не появилась и по решению пользователя отложена; стендовые ad-проверки не заменяют live-рекламу. Внутренний setter скорости и DOM YouTube могут измениться — реальные проверки остаются обязательными при обновлениях адаптера. Публичный выпуск, хранение списка комнат и явная смена видео относятся к следующим изменениям MVP.
