Обнаруженная проблема: транспорт по умолчанию пытался использовать JSONP long polling; при reload подписка не восстанавливалась, браузер блокировал внешний script по CSP. Это означает зависимость подключения от доступности WebSocket; поведение UI при недоступной сети ещё относится к задачам транспорта/reconnect.

Особенности инструментария: настоящий popup не представлен обычной Playwright Page, поэтому управляется через `chrome.action` и `chrome.runtime.getContexts`. При MV3 suspension Playwright сохраняет Worker object и не испускает `close`; доказательство остановки — CDP runningStatus, доказательство перезапуска — новый случайный instance внутри worker. Естественный idle timeout не измерялся при подключённом debugger.

Воспроизводимая browser-проверка — `npm run test:firebase-context`: один сценарий покрывает всю матрицу. Он запускает и останавливает эмуляторы сам, сохраняет компактное JSON-приложение результата и trace при ошибке. Секретов приглашений в стенде нет; журналы Auth и trace не публикуются.

## Основной Auth и room transport — задача 2.1

Контекст из 1.3 перенесён в основной `src/`: `lib/firebase/client.ts` сериализует IndexedDB hydration и Anonymous Auth через общий Web Lock; `lib/room/transport.ts` читает одну комнату и следит за соединением/смещением серверного времени. `entrypoints/watch-session.content.ts` создаёт iframe по внутреннему запросу popup. `session/main.ts` владеет transport и принимает только собственный popup с валидной схемой сообщения и адресом получателя. Нет page-world API или postMessage bridge; UID, Auth и секрет не попадают в URL/DOM страницы. Полномочия content script ограничены созданием iframe; его сообщения не дают читать room data или выбирать комнату.

Окружение прежнее: Node 24.19.0, bundled Chromium 156, свежие persistent profiles, основной `src/` с `WXT_FIREBASE_EMULATORS=1`, локальный demo-проект. Обычная сборка содержит тот же код и разрешения YouTube, но без локального флага не выполняет Firebase-запросов. Облачная конфигурация пока отсутствует. Проверка доступна через `npm run test:transport`; opt-in `YOUTUBE_TRANSPORT_REAL=1 npm run test:transport` добавляет настоящий сайт.

## Offline/reconnect — задача 3.5

2026-11-02. Transport разделяет доступность основного соединения (`connected`) и готовность актуальной комнаты (`roomReady`). После выбора комнаты и каждого reconnect синхронизация ждёт чтения сервера временным Firebase SDK app с пустым cache. Auth в памяти получает копию действующего Anonymous User через `updateCurrentUser`; нового входа/UID нет. Чтение идёт через WebSocket, секрет и токен не добавляются в HTTP URL. Временный клиент не создаёт presence и закрывается в finally; обрыв, выход, смена комнаты и таймаут 15 с отменяют ожидание. При ошибке остаётся блокировка sync и появляется повтор подключения.

Снимок чтения может отстать от подписки. Playback выбирается по большей revision, а presence остаётся за основной подпиской, поскольку у него нет общей с playback версии. При обрыве engine отсоединяет адаптер и сбрасывает незавершённые intent/apply, сохраняя локальное воспроизведение. Поколение соединения и AbortSignal защищают ожидание начального snapshot и повторные callbacks транзакции. Поздний ack или ошибка старой отправки не управляют восстановленным плеером. Offline-действия не накапливаются; после чтения применяется последнее состояние комнаты, новое действие получает актуальную базовую revision.

Новая матрица `tests/room-transport/reconnect.spec.ts` запускает два независимых persistent profiles, настоящий popup/приглашение и общий DOM/media-стенд. ## Нативная скорость — продолжение 4.4

2026-11-02, Node 24.19.0, bundled Chromium 156.0.8078.4, свежие profiles без аккаунтов YouTube. Пользователь поручил исправить рассогласование скорости; естественная реклама остаётся отложенной.

## Обычный Chrome без Playwright — 2026-11-03

В двух новых независимых профилях установленного Chrome через native Computer Use выполнено 31 действие в облачной комнате: Play/Pause, перемотка и выбор скорости в меню передавались в обе стороны. Оба плеера оставлены на паузе: 354,7 с, ×1,5; участников — 2. Пользователь также отдельно подтвердил нормальный просмотр после минуты в обычном Chrome и в новом профиле без Playwright.

Нативное меню после удалённой смены скорости показывает правильные 1,25×. Отдельное отклонение: при русской раскладке `Shift + Period` меняет скорость локального YouTube на 1,5×, но состояние комнаты и второго плеера остаётся 1,25×. Дальнейшая диагностика сброса должна учитывать различие обычного и автоматизированного запуска; конкретный механизм YouTube/сети не установлен. ## Ограничения и оставшиеся эксперименты

- Popup определяет обычную watch-страницу и в локальной сборке подключает session/Auth. При создании проверяет готовность через DOM-адаптер; текущая DOM-эвристика не гарантирует поддержку всех layouts и региональных ограничений YouTube.
- Начальный E2E открывает popup.html как extension page. Отдельная transport-матрица проверяет создание комнаты через настоящий action popup и вход второго profile через приглашение и открытие/повторное использование связанной watch-вкладки. Базовая синхронизация плеера реализована в 3.3; результаты и ограничения приведены ниже.
- Интеграционный тест 1.2 использует SDK instances с непостоянной Auth; browser experiment 1.3 отдельно подтверждает два profiles, общий UID внутри профиля и его сохранение после reload/worker restart. Полный перезапуск браузера, incognito и очистка storage не проверялись.
- Локальные Rules комнат проверены в 2.2; полный секрет даёт доступ любому авторизованному клиенту. Membership, срок приглашений и удаление пустых комнат остаются вопросами публичного MVP. `_probes` сохранён для локального стенда.
- `npm audit` при настройке основы: 20 предупреждений (16 moderate, 4 high). High связаны с gRPC в неиспользуемом Firestore, который входит в umbrella-пакет Firebase; moderate — с транзитивными зависимостями локального Firebase CLI. `npm audit fix` не устранил их в рамках закреплённых версий. Принудительное понижение Firebase/CLI и подмена транзитивных версий не выполнялись. Основной и экспериментальный код импортируют только app, auth/web-extension и database. В 2.1 версии зависимостей не менялись; новый audit не выполнялся.
- Основной transport чтения, sender checks и iframe/Auth на настоящем YouTube проверены в 2.1. Presence через onDisconnect и reconnect проверены на локальном стенде в 2.5. Восстановление привязки после reload и остановки worker проверено в 2.6. Общие команды плеера проверены в 3.3 и облачных замерах 4.3; другие версии Chrome не проверены. Auth-токены, UID и секреты не передаются странице через postMessage.
- Контролы и локальность buffering проверены на реальном YouTube; недоступный ролик, autoplay и SPA — в 1.5. Настоящая реклама не подтверждена и отложена пользователем. ADR-0003 принят для прототипа; удалённый rate/menu и клавиши при русской раскладке исправлены и проверены.
- В облаке измерены p95 и расхождение для готовых плееров на общем хосте и маршруте. Buffering исключается из численной выборки. Длинные автоматизированные попытки останавливаются после сброса media, в том числе без расширения/Firebase; причина различия запусков не установлена. Итоговый обычный Chrome дал 31 пригодный замер из 48, подтвердил точные критерии и отсутствие эха. Другие сети и географии этим не проверены.
