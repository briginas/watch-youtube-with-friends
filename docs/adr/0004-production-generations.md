# ADR 0004. Поколения production backend

Принято 2026-11-04. Production rollout выполняется отдельно.

Firebase RTDB и Anonymous Auth из ADR 0002 остаются сервером комнаты. Несовместимый
контракт получает новый backend project и новое поколение. Совместимые версии
расширения используют один backend и один неизменяемый снимок контракта.
Состояние комнат и локальные привязки между поколениями не переносятся.

Постоянный control Hosting обслуживает приглашения, privacy, публичный реестр и
временные статусы. Поколение и ключ комнаты хранятся во fragment. Реестр сообщает
о поддержке и не управляет выбором RTDB. Legacy-ссылки зависят от прежнего Hosting.

Лимит в три работающих backend включает подготовленный проект. При достижении
лимита оператор отмечает старейшее поколение retired, проверяет опубликованный
реестр и только после этого запрашивает удаление. Облачная квота проверяется
отдельно, включая проекты в состоянии DELETE_REQUESTED.

Один постоянно изменяемый backend потребовал бы совместимости всех контрактов.
Новый проект для каждого patch быстро исчерпал бы квоту. Служебный Hosting в
backend привязал бы срок жизни новых ссылок к удаляемому проекту. Пересмотр нужен,
если потребуется перенос комнат между поколениями или другой предел проектов.
