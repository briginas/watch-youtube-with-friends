# Watch Youtube with friends

Chrome-расширение для совместного просмотра прямо на YouTube с обычным интерфейсом плеера.

## Быстрый старт

Нужны Node.js из `.nvmrc` и npm. Для тестов Firebase Emulator Suite нужен JDK 21+.

```sh
nvm use
npm ci
npm run typecheck
npm test
npm run build
```

В Chrome откройте `chrome://extensions`, включите режим разработчика и загрузите
`.output/chrome-mv3` как распакованное расширение. Эта сборка работает без сервера;
для совместного просмотра настройте своё окружение.

```sh
npm run config:init
# Заполните .env.cloud для QA или .env.production и .local/deployment для production.
npm run build:cloud
# Либо для своего production:
npm run release:build
```

QA-сборка: `.output/cloud/chrome-mv3`. Production-сборка: `.output/release/chrome-mv3`.
Реальные настройки, инвентарь и внутренние отчёты не входят в Git.
[Настройка окружений](docs/configuration.md) · [Подготовка к GitHub](docs/github.md).
Команды сборки не выполняют deploy.

## Состояние проекта

Технический прототип принят 2026-11-03, **22/22 задачи**, ADR-0002/0003 приняты для прототипа. Есть MV3-расширение на WXT/TypeScript/React, popup, Anonymous Auth, создание комнаты из текущего видео, приглашения, presence и выход, локальные Firebase-эмуляторы и облачная QA-сборка. Вход открывает связанную YouTube-вкладку либо активирует существующую. Sync engine передаёт play/pause, seek и скорость между участниками; после локальных ограничений и reconnect применяется последнее состояние. Offline-действия не накапливаются. На настоящем YouTube проверены sync, autoplay, buffering, конфликты, сеть и обрывы транзакций, popup/worker/reload, SPA и выход создателя. Естественная реклама отложена пользователем за пределы текущей приёмки.

Итоговая облачная приёмка в двух обычных профилях Chrome: **48 команд, 31 пригодный замер, p95 228 мс, максимальное расхождение 0,178 с через 3 с**. Все 48 команд приняты с правильным автором и одной revision, без эха; 17 исключены из численной выборки из-за buffering. Исправлены повторные apply, распознавание ошибки плеера и скорость: нативное меню и клавиши при английской/русской раскладках согласованы после удалённого применения. [Отчёт, исходные данные и воспроизведение](docs/experiments/youtube-native-acceptance-2026-11-03.md).

Громкость/mute, качество и субтитры остаются личными настройками. Двухпрофильный сценарий `tests/room-transport/local-settings.spec.ts` проверяет их локальность и сохранение после общей перемотки; `YOUTUBE_TRANSPORT_REAL=1` добавляет настоящий YouTube. Эти поля запрещены в общей модели и RTDB Rules.

Измерения выполнены на одном Mac и общем маршруте; независимые сети и географии не проверены. Длинный автоматизированный cloud E2E через Playwright по-прежнему прерывается внешним сбросом media, воспроизводимым без расширения/Firebase; причина различия запусков не установлена. В итоговом обычном Chrome сброс не повторился. Все неудачные попытки сохранены в [журнале](docs/experiments/youtube-sync-prototype.md). Принятие прототипа не означает готовность всего MVP.

## Оформление popup

Popup использует выбранные плюшевые иконку и обложку, просторные карточки и крупные
кнопки. По умолчанию включена светлая сливочная тема. Переключатель с луной/солнцем
в заголовке включает тёмную сливовую палитру той же компоновки; выбор сохраняется
в текущем профиле браузера. Тема не меняет оформление дока на YouTube.

## Список комнат (room-catalog)

Popup показывает «Мои комнаты» на любой странице. Подтверждённое создание и успешное принятие приглашения сохраняют комнату в `storage.local` текущего профиля; серверные окружения разделены по настройкам Firebase и приглашений. Доступ content scripts к этому хранилищу закрыт. Список не создаёт presence и не подключает комнаты автоматически после перезапуска. «Открыть» активирует связанную вкладку или открывает новую с актуальным состоянием.

Выход и закрытие вкладки сохраняют запись. «Убрать из списка» удаляет только локальную запись: открытый просмотр продолжается, приглашение и данные сервера сохраняются. Пустые комнаты и приглашения не имеют автоматического срока истечения. При ошибке локального сохранения уже открытая комната продолжает работать; session-индикатор предлагает «Повторить сохранение». Ошибка удаления сохраняет запись в списке и допускает повтор.

Каждая комната хранит имя в `metadata.name`. Новые комнаты получают имя вида «🎬 0042» с четырьмя случайными цифрами. Метки могут совпадать. Ранее созданные комнаты используют сохранённые имена. Комнаты без metadata имеют неподдерживаемый формат.

[Проверка списка комнат в двух обычных Chrome profiles, 2026-11-03](docs/experiments/room-catalog-native-2026-11-03.md): название реального видео, список вне YouTube, повторное открытие, независимые комнаты и удаление записи при продолжающемся просмотре.

## Явная смена видео (room-video-switch)

P-08: в связанной вкладке после перехода на другой записанный ролик действие «Смотреть это в комнате» предлагает его комнате с текущими позицией, скоростью и play/pause. Простой переход остаётся локальным. Следующие за комнатой участники переходят на новое видео в прежних вкладках; ушедший смотреть свой ролик сохраняет локальный просмотр, в том числе после reload, до действия «Вернуться в комнату», собственного перехода на актуальное общее видео или подтверждённой собственной смены. Название и приглашение комнаты сохраняются. При ошибке или отсутствии связи можно явно повторить действие; offline-запросы не накапливаются.

**Breaking contract:** playback требует `kind` (`playback`/`switch-video`) и `videoRevision` — поколение общего просмотра. При создании `revision = videoRevision = 0`; смена назначает поколению номер новой revision. Обычные команды прежнего поколения запрещены, в том числе после A → B → A. Старые серверные комнаты не поддерживаются и не мигрируют; для новой сборки нужны актуальные Database Rules и новые комнаты. Формат каталога не меняется, но его записи могут указывать на неподдерживаемые старые комнаты.

[Проверки и ограничения](openspec/changes/archive/2026-11-03-room-video-switch/verification.md). [Native QA в двух обычных Chrome profiles, 2026-11-03](docs/experiments/room-video-switch-native-2026-11-03.md): смена от обоих участников на реальном YouTube, прежнее приглашение, detached после reload и возврат, отсутствие лишних revision и восстановления удалённой записи. Естественная реклама остаётся отложенной проверкой.

## Интерфейс комнаты на странице (room-page-ui)

В связанной watch-вкладке индикатор внизу слева показывает название комнаты, состояние и число участников. Нажатие раскрывает участников, приглашение, выход и доступные действия возврата/смены видео. Повторное нажатие или Escape сворачивает подробности; подключение и общее воспроизведение продолжаются. После reload подробности свёрнуты. Кнопки доступны через Tab и Enter/Space.

Индикатор различает совместный и локальный просмотр, подключение, отсутствие связи, рекламу, загрузку и запрет autoplay. При неизвестном составе вместо числа показано «—». Ошибки отмечаются в индикаторе; объяснение и повтор находятся в подробностях. Число включает подключённого участника, который смотрит свой ролик локально.

Панель можно перемещать левой кнопкой мыши за заголовок с названием комнаты. Короткий клик по-прежнему раскрывает подробности; перетаскивание не раскрывает их и не управляет видео. Панель остаётся внутри окна при перемещении, раскрытии и изменении размера. Положение сохраняется в текущем документе, включая SPA-переходы и выход из fullscreen; после reload возвращается в нижний левый угол.

«Копировать приглашение» доступно создателю и гостю, включая после reload и остановки worker. При отказе clipboard можно выделить ссылку вручную внутри панели расширения. Копирование не восстанавливает убранную из каталога запись.

Заголовок связанной watch-вкладки имеет вид `🎬 4812 | Текущий заголовок YouTube`. Название комнаты сохраняется при смене видео, локальном просмотре и потере связи; остальная часть следует за YouTube. Выход через страницу или popup снимает префикс. При SPA-уходе за пределы watch панель и префикс скрываются, привязка сохраняется; возвращение на watch восстанавливает отображение. В fullscreen панель явно скрывается, включая fullscreen корневого элемента страницы. После выхода возвращается с прежним состоянием раскрытия; соединение и префикс title сохраняются. Выход из комнаты через popup во время fullscreen не восстанавливает завершённую сессию.

Изменение завершено: 14/14 задач, требования синхронизированы с основной spec. Обработка отказа clipboard принята по browser-тесту с искусственной ошибкой. Проверки и ограничения: [room-page-ui verification](openspec/changes/archive/2026-11-03-room-page-ui/verification.md), [native QA в двух Chrome profiles](docs/experiments/room-page-ui-native-2026-11-03.md).

Скрытие панели в fullscreen и перемещение завершены: 8/8 задач, drag в обычном Chrome подтверждён пользователем. Требования перенесены в основную spec; [review](openspec/changes/archive/2026-11-04-room-panel-position/review.md) и [проверки](openspec/changes/archive/2026-11-04-room-panel-position/verification.md) сохранены в архиве.

## Локальная разработка

Нужны Node 24 LTS (версия закреплена в .nvmrc) и JDK 21+. На macOS Java можно установить командой `brew install openjdk@21`; команды эмуляторов автоматически находят её в стандартном каталоге Homebrew. На других платформах Java должна быть в PATH или JAVA_HOME.

```sh
nvm use
npm ci
npm exec -- playwright install chromium --no-shell
npm run typecheck
npm test
npm run test:e2e
npm run test:integration
npm run test:firebase-context
```

`npm run dev` запускает WXT с браузером. Обычный `npm run build` создаёт сборку без настроек сервера в `.output/chrome-mv3`. В ней можно проверить интерфейс, а кнопка «Смотреть вместе» будет недоступна.

Для совместного просмотра с рабочим сервером запустите `npm run release:build` с настроенным `.env.production`. На `chrome://extensions` включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите `.output/release/chrome-mv3`. Настройка окружения описана в [инструкции выпуска](docs/release.md#сборка-и-аудит).

## Локальный Firebase

```sh
npm run emulators
```

Используется только demo-проект `demo-watch-together`: Firebase login, production credentials и облачные ресурсы не нужны. При первом запуске CLI скачивает эмулятор RTDB. Auth слушает 127.0.0.1:9099, RTDB — 127.0.0.1:9000, Hosting — [127.0.0.1:5002](http://127.0.0.1:5002). Порт Hosting выбран с учётом занятого Control Center порта 5000 на macOS.

`npm run test:integration` самостоятельно запускает и останавливает эмуляторы; отдельно запускать `npm run emulators` перед ним не нужно. RTDB Rules разрешают Auth-пробы в `_probes` и доступ к одной комнате по полному секретному ключу после Auth. Корень и список комнат закрыты; playback проверяется по структуре, автору, серверному времени и revision, presence можно менять только для собственного UID. Матрица Rules использует настоящие Anonymous ID tokens без admin-доступа и подмены правил. `_probes` остаётся локальным стендом; облачный деплой ещё не настроен.

`npm run test:firebase-context` запускает отдельный эксперимент с двумя Chromium profiles: общий Auth внутри профиля, закрытие настоящего popup, остановка worker и восстановление данных. По результатам выбран extension-origin документ во вкладке просмотра. Подробности — в [отчёте](docs/experiments/youtube-sync-prototype.md#firebase-контекст-и-mv3--задача-13).

## Auth и room transport

В основном коде добавлен `session.html`, который popup подключает к открытой watch-вкладке через content script. Документ владеет RTDB-подписками, popup использует общий Anonymous UID; worker не держит соединение. UID, Auth и данные комнаты не передаются странице YouTube. Обычный manifest теперь разрешает content script и iframe на YouTube; localhost добавляется только в сборке с эмуляторами.

```sh
npm run test:transport
# Дополнительно проверить iframe и Auth на настоящем YouTube:
YOUTUBE_TRANSPORT_REAL=1 npm run test:transport
```

Команда собирает основной `src/` с локальной конфигурацией в `.output/room-transport/chrome-mv3`, запускает эмуляторы и browser-матрицу. Для ручной проверки: `npm run build:transport`, `npm run emulators`, загрузить эту сборку и открыть popup на watch-странице. После подключения «Смотреть вместе» создаёт комнату с текущими videoId, позицией, скоростью и play/pause. «Копировать приглашение» записывает ссылку в clipboard; при отказе копирования её можно выделить вручную. При рекламе или неготовом плеере предлагается повторить попытку позднее.

Transport создаёт и читает одну комнату по внутренним запросам popup, отслеживает соединение и смещение серверного времени, снимает подписки при переключении и закрытии. Ссылка появляется после серверного подтверждения записи; её секрет находится только во fragment (`#room=…`). Повторное открытие popup в той же вкладке возвращает ту же ссылку. Ссылка локальная (`http://127.0.0.1:5002/`); привязка watch-вкладки хранится в `storage.session` и восстанавливается после reload и остановки worker в текущем сеансе браузера. После создания команды плеера передаются через sync engine.

Чтобы проверить приглашение, откройте скопированную ссылку во втором Chrome profile с той же локальной сборкой. Кнопка «Присоединиться» выполняет Anonymous Auth и проверяет существующую комнату, затем открывает отдельную YouTube-вкладку или активирует уже связанную, включая вкладку создателя. Документ `session.html` во вкладке просмотра подписывается на актуальное состояние; приглашение снимает свою подписку и не создаёт presence. Повреждённая ссылка, отсутствующая комната и отказ доступа дают отдельные сообщения. Без расширения видна инструкция установки unpacked-прототипа. Bridge включён только для `http://127.0.0.1:5002/`; другой порт, путь и origin не обслуживаются. UID и данные не передаются hosting-странице. Повторные и одновременные приглашения используют одну связанную вкладку. Закрытие вкладки и явный выход удаляют привязку; reload после выхода не возвращает пользователя в комнату. Секрет не добавляется в URL YouTube или iframe и не передаётся content script. Актуальное состояние применяет sync engine.

После создания или входа видны число участников, разные номера/цвета, отметка «вы» и кнопка «Выйти из комнаты»; они есть в extension-индикаторе на странице и popup создателя. Один Anonymous UID считается одним участником. При входе по приглашению соединение принадлежит связанной watch-вкладке; закрытие страницы приглашения не выводит из комнаты. Каждое соединение имеет отдельный presence с серверной уборкой `onDisconnect`; reconnect заново регистрирует его. Выход снимает подписку и собственное соединение, не меняя playback и права остальных; закрытие последнего документа также снимает присутствие. Номера и цвета вычисляются по текущему составу, поэтому при входе/выходе могут измениться. При отсутствии связи список скрывается. Присутствие не управляет плеером; синхронизацией занимается отдельный engine.

Проверки создания используют продуктовые RTDB Rules; отдельный сценарий временно запрещает запись и проверяет повтор после отказа. Исходная lifecycle-матрица transport использует собственные read-only fixture Rules; обе проверки восстанавливают исходные Rules. Полная матрица серверного доступа — `npm run test:integration` (задача 2.2). Для копирования основной manifest содержит `clipboardWrite`; доступ к чтению clipboard продукту не предоставляется.

## Эксперимент с плеером

Общая модель playback и расчёт позиции находятся в `src/lib/playback/model.ts`; команды с baseRevision/commandId — в `src/lib/playback/commands.ts`, sync engine — в `src/lib/playback/engine.ts`. Session-документ передаёт адаптеру только videoId и целевые position/rate/play/pause через внутренние extension messages. Секрет комнаты, UID и Auth остаются в extension-документе. Пользовательские намерения вызывают `sendCommand` и RTDB-транзакцию; повторные/старые revision и подтверждения собственных действий не применяются заново. При конфликте побеждает более позднее пользовательское действие по `actionAt`, даже со старой baseRevision; при равных метках сохраняется первая принятая команда. Время считывания позиции `sampledAt` учитывает ожидание отправки и задержку сети; `updatedAt` остаётся серверной меткой записи. Обе клиентские метки переводятся в серверные часы через Firebase offset и не зависят от timezone; точность порядка близких действий ограничена погрешностью offset. Обе метки обязательны во всех playback, включая начальную версию комнаты; обратная совместимость не поддерживается. При выходе адаптер отключается. Реклама, buffering и autoplay остаются локальными; после готовности engine применяет последнее состояние. Session-индикатор показывает ограничение и необходимость первого play.

Перемотка мышью или клавиатурой передаётся после отпускания и 120 мс без новых событий перемотки, когда media завершила seek. Автоповтор удерживаемой клавиши не создаёт промежуточных команд. Пока пользователь выбирает позицию, входящая синхронизация ждёт; blur/pointercancel отменяет жест. Если предыдущая отправка ещё идёт, engine сохраняет только последнее следующее действие с исходными метками, без возврата к промежуточной позиции. Более позднее удалённое действие отменяет устаревшее ожидающее; disconnect и локальная недоступность очищают его.

После reconnect transport сначала читает комнату с сервера временным SDK-клиентом без cache, с тем же Anonymous UID. Пока чтение не завершилось, общие команды и применение к плееру заблокированы; UI показывает получение актуального состояния, при ошибке — повтор подключения. Более новая revision подписки имеет приоритет над запоздавшим снимком, presence остаётся за подпиской. Обрыв отменяет ожидание начального snapshot команды и отсекает результаты предыдущего соединения. `tests/room-transport/reconnect.spec.ts` проверяет offline до записи и обрыв транзакции до доставки серверу/до получения ack, с новой командой другого участника и без неё. Это проверки двух profiles на управляемом видеостенде под продуктовыми Rules; настоящая сеть YouTube и облако остаются в 4.2–4.3.

`tests/room-transport/sync.spec.ts` проверяет оба направления управления в независимых profiles, настоящий плеер и серверную revision после асинхронных media events. Входит в `npm run test:transport`; `YOUTUBE_TRANSPORT_REAL=1` добавляет реальный YouTube. Для ручного прогона запустите эмуляторы и `SYNC_MANUAL=1 YOUTUBE_TRANSPORT_REAL=1 npx playwright test --config playwright.transport.config.ts sync.spec.ts`: откроются два окна Chromium с вкладками `Sync QA — A/B`. Выполните в A play, pause, seek вперёд и увеличение скорости через меню, затем в B play, pause, seek назад и увеличение скорости через меню. Проверка ждёт реальные действия через UI, сверяет авторство, состояние обоих плееров и отсутствие дополнительных revision; наблюдения сохраняются в test-results.

`tests/room-transport/restrictions.spec.ts` проверяет в двух profiles локальность рекламы/buffering, восстановление с новой revision и без неё, а также настоящий отказ autoplay и первый разрешающий play без общей команды. Реклама и waiting здесь воспроизводятся на управляемом видеостенде; autoplay использует настоящую browser policy, CDP не выдаёт watch-странице user activation. `YOUTUBE_TRANSPORT_REAL=1` добавляет два сценария autoplay на настоящем YouTube. Естественная реклама остаётся отдельной непроверенной частью 1.4/4.2.

`npm run test:player` собирает отдельное MV3-расширение с DOM-адаптером и проверяет его на управляемом видеостенде. `npm run test:player:youtube` запускает отдельную opt-in матрицу настоящего YouTube: контролы, применение команд, локальная буферизация, недоступный ролик, SPA-навигация, запрет autoplay и наблюдение естественной рекламы. Она зависит от сети, региона и текущего интерфейса сайта; отсутствие рекламы обозначается skipped. Результаты — в [журнале](docs/experiments/youtube-sync-prototype.md#адаптер-плеера--задача-14-частично).

Для ручной проверки: `npm run build:player-probe`, затем загрузить `.output/youtube-player/chrome-mv3` как unpacked extension и открыть обычный ролик. В левом нижнем углу отображается `Player probe: ready/ad/buffering/...`. Пробы запускаются в isolated content script; host permission на YouTube добавляется только в экспериментальную сборку. Комнат и Firebase в этой пробе нет. Подробности — в [инструкции стенда](experiments/youtube-player/README.md).

## OpenSpec

CLI устанавливается локально как devDependency; точная версия закреплена в package.json и package-lock.json.

```sh
npm ci
npm run spec:validate
npm exec -- openspec status --change youtube-sync-prototype
```

Инструкции OpenSpec для AI находятся в .agents/skills/. Согласованные требования завершённого прототипа находятся в `openspec/specs/`, его план и результаты — в `openspec/changes/archive/2026-11-03-youtube-sync-prototype/`. Новое поведение оформляется отдельным change.

## Тестовое облако

Публичный выпуск использует отдельное production-окружение. Команды сборки, аудит ZIP,
privacy и фактический статус публикации — в [инструкции выпуска](docs/release.md).

Для задачи 4.3 создан отдельный Firebase-проект `example-qa`: RTDB в `europe-west1`, Anonymous Auth и страница приглашения. IDs в публичной документации — примеры; рабочие настройки хранятся локально.

`npm run build:cloud`, `npm run deploy:cloud`, `npm run deploy:rules` и `npm run test:cloud` используют локальный `.env.cloud` и отдельную сборку `.output/cloud/chrome-mv3`. Образец публичных настроек — `.env.example`; ключи service account в расширение не добавляются. `deploy:rules` публикует только Database Rules, без Hosting и Auth. Методика измерений и подготовка проекта — в [инструкции](docs/experiments/cloud-measurement.md). Обычная сборка без настройки сервера остаётся отключённой от Firebase.
