# Работа с изменениями

1. **OpenSpec.** Если меняется поведение расширения, его требования или контракт между компонентами, создай или продолжи подходящий OpenSpec change. Зафиксируй ожидаемое поведение и сценарии проверки до реализации. Правки опечаток, документации, тестов или внутреннего кода можно делать без отдельного change, если требования и поведение остаются прежними. Следуй [процессу разработки](docs/development.md) и инструкциям в `.agents/skills/`.
2. **Версия расширения.** При подготовке релиза повысь версию один раз по самому существенному изменению в пакете с прошлого выпуска. Используй `patch` для исправлений и небольших улучшений, `minor` для новых обратно совместимых возможностей, `major` для намеренных несовместимых изменений. Обновляй `package.json` и `package-lock.json` вместе и подготовь дескриптор по [инструкции выпуска](docs/release.md). Совместимость с поколением backend определяй отдельно от номера версии. Для локальной проверки используй метку сборки в деталях расширения на `chrome://extensions`. Она формируется автоматически и содержит версию пакета, короткий SHA коммита и время в UTC. Пометка `dirty` указывает на незакоммиченные изменения, `no-git` — на отсутствие сведений о коммите.
3. **Сборка для Chrome.** Для ручной проверки совместного просмотра с рабочим сервером запусти `npm run release:build` с настройками из `.env.production` и укажи пользователю путь к `.output/release/chrome-mv3`. Обычный `npm run build` создаёт `.output/chrome-mv3` без настроек сервера, поэтому «Смотреть вместе» в ней недоступна. Подробности — в [инструкции выпуска](docs/release.md#сборка-и-аудит).
4. **Завершение OpenSpec.** После реализации выполни проверки и отметь выполненные задачи. Когда все обязательные проверки пройдены, синхронизируй delta specs с основными спецификациями, заархивируй change и запусти `npm run spec:validate`. Завершённый change архивируй в рамках той же задачи.
5. **Коммит.** После проверок сделай локальный коммит с файлами текущей задачи. Включи обновлённые спецификации, архив change и файлы версии, если они менялись в рамках задачи. Чужие и несвязанные правки оставь вне коммита.
