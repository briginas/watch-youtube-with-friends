# Verification — 2026-11-11

## Причина и исправление

Адаптер не считал выбор главы пользовательским seek: Ctrl/Alt отбрасывались,
а pointer-контролы распознавались только внутри плеера. Новый browser-тест клика
на исходном коде воспроизвёл отсутствие intent при фактическом изменении позиции.
Добавлены главы списка, ссылки времени текущего видео и Ctrl/Option+стрелки.
Существующие подтверждение media events, debounce, release timestamp и защита
незавершённого жеста сохранены.

## Автоматические проверки

- `npm run typecheck` — успешно, включая повтор на Node 24.19.0.
- `npm test` — 38 файлов, 306 тестов успешно.
- Player suite — 32 теста успешно; после корректировки расположения глав на стенде
  и защиты парсинга URL повторены все 11 chapter-тестов, успешно.
- Transport с Auth/RTDB/Hosting Emulator Suite и продуктовыми Rules:
  глава мышью, Ctrl/Option, timestamp, Enter/Space — одна revision на действие,
  оба участника в новой позиции, без отката и эха. Пройдены проверки личных
  настроек и все четыре сценария seek-order.
- Первый transport-прогон: 4 passed, 2 skipped (opt-in YouTube), 2 timeout.
  Новый тест перекрывался абсолютно позиционированным плеером; исправлена только
  компоновка fixture. Повтор главы и завершившегося по timeout существующего
  сценария более позднего удалённого действия — 2 passed, 14,5 с.
- В sandbox Chromium завершался с SIGABRT/EPERM до выполнения теста;
  browser-проверки выполнены с разрешённым запуском вне sandbox.

## Настоящий YouTube

Отдельный opt-in тест использует ролик пользователя
https://www.youtube.com/watch?v=nKjPBAw_N_0.
Начальные попытки выявили помехи стенда: окно cookies с отличающимся aria-label
кнопки отказа и гонку с начальным autoplay. В тест добавлены закрытие окна и
устойчивое начальное состояние через существующий apply.
Финальный запуск на Node 24.19.0 / Chromium 156 — **1 passed, 7,4 с**,
включая явные assertions позиции 141 с для обоих способов перехода.
Нативный DOM подтверждён: `ytd-macro-markers-list-item-renderer`, ссылка главы
`/watch?v=nKjPBAw_N_0&t=141s`. И мышь, и Option+ArrowRight создают ровно один seek.
Проверка начинается с `t=137s` и выполняет оба перехода к 2:21 в начальном
загруженном диапазоне. Попытка перехода с начала ролика к 2:21 оставалась в
buffering: ввод распознан, но media seeking не завершился за 20 с.
Загрузка далёких диапазонов этим успешным запуском не подтверждена.
YouTube при переходе по главе может сам запускать видео; передаётся фактическое
состояние после перехода, без изменения поведения нативного контрола.
Два участника проверяются на управляемом media-стенде; это не проверка двух
реальных YouTube-плееров с облачным backend.
