# Review: room-page-ui

Проверены delta spec, design, изменения `src/`, адаптация transport suites и пользовательская документация. Объём PRD P-07 отражён отдельной записью; историческое описание технического прототипа сохранено.

## Реализация

- Transport и sync engine остаются в прежнем extension iframe. Сворачивание меняет только DOM и геометрию, не вызывает команд воспроизведения, переподключения или новых подписок.
- Модель краткого состояния приоритетно показывает ошибки/offline/ожидание актуальных данных. Счётчик и список скрывают неактуальный presence. Detached и ограничения плеера имеют отдельные состояния.
- Presentation проверяется строгой схемой, адресом отправителя и текущим target; монотонная sequence отсекает задержанные сообщения. Передаются название, видимость и размеры; секреты комнаты, UID и Auth в этом сообщении отсутствуют.
- Ссылка строится из принятой привязки внутри session; каталог для этого не читается и не восстанавливается. Ошибка clipboard даёт read-only поле внутри iframe. Поздний результат копирования после выхода игнорируется.
- Контроллер title хранит собственный результат и актуальную внешнюю строку. Он не удаляет похожие чужие префиксы; очистка и invalidation снимают только собственное изменение.
- Успешный release сначала подтверждает удаление привязки, затем скрывает UI и снимает подписку. Неуспешный release оставляет комнату и доступный повтор.

## Исправления при проверке

Измерение скрытого iframe переведено с `requestAnimationFrame` на отложенный timer: скрытый документ мог не получить animation frame и никогда не показать индикатор. Добавлены измерение при resize и дедупликация одинаковых presentation-сообщений, чтобы ограничение высоты не поддерживало постоянный обмен. Ошибки reconcile отделены от результата общей смены, синхронный отказ clipboard обрабатывается вместе с отклонённым Promise.

Дополнительно учтена нормализация ASCII-пробелов при чтении HTML `document.title`. Контроллер запоминает фактический результат и не записывает собственный заголовок повторно из observer; смена управляемого имени остаётся отдельным принудительным обновлением. Регрессия с несколькими пробелами/переносом проверяет один префикс, отсутствие повторных записей и очистку после выхода.

Старые тесты раскрывают подробности перед действиями; технические проверки playback используют существующий extension status-запрос. Сценарий выхода за пределы watch теперь проверяет скрытие host и возвращается на watch перед действием возврата. Проверки серверных revision, presence, Auth и настоящего запрета autoplay сохранены.

В headless Chromium 156 доставка мышиного события во вложенный extension iframe в некоторых сценариях не происходила при правильных bounds и успешном Playwright click. Для действий панели в затронутых тестах используется настоящий keyboard Enter с фокусом. DOM dispatch кликов не добавлялся. Нативные клики мышью независимо подтверждены в обычном Chrome; ограничение драйвера не выдаётся за проверку всех mouse-сценариев.

## Границы результата

Adapter, engine, RTDB Rules, серверные контракты, manifest permissions и dependencies не изменены. Дополнительные player/Rules suites не требуются из-за изменения этих компонентов; их регрессии покрывает основной transport suite.

Фактические команды и результаты — в [verification.md](verification.md). По согласованной с пользователем 2026-11-03 методике обработка отказа clipboard и показ ручной ссылки приняты по browser-тесту с искусственным отклонением `writeText()`. Успешное копирование обоими участниками проверено в обычном Chrome; естественный отказ и ручное копирование там не наблюдались и не выдаются за пройденный native-сценарий. Все 14 задач выполнены по уточнённым критериям; требования синхронизированы с основной spec, change архивирован. Естественная реклама остаётся отдельной неподтверждённой проверкой. Деплой и публикация не выполнялись.
