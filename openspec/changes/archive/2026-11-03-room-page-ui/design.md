# Design

## Context

Мотивация и границы — [proposal.md](proposal.md), наблюдаемое поведение — [delta spec](specs/room-session/spec.md).

Прочитанная реализация:

- `watch-session.content.ts` создаёт фиксированный host 280×250 px с закрытым Shadow DOM и extension iframe. Он же владеет адаптером плеера; session target связывает сообщения с конкретным документом.
- `session/main.ts` владеет transport и sync engine. DOM обновляется из transport callback, reconcile и player events. Закрытие popup не останавливает просмотр; worker сериализует привязки в `storage.session`.
- `session.html` показывает технические connection/playback строки, локальные ошибки, участников и действия. Названия и приглашения здесь нет, `document.title` YouTube не управляется.
- `room-tab-ready` возвращает действующему session-документу привязку с key/name/view. При создании эти значения уже известны session. `transport.invitation` заполняется при создании, но не при `watchRoom`, поэтому его недостаточно для гостя или reload.
- `presence-ui.ts` скрывает участников при offline, но не учитывает все случаи неактуального состояния; счётчик индикатора должен учитывать `roomReady` и `presenceError`.
- В manifest уже есть `clipboardWrite`. Сценарии transport проверяют настоящее session iframe, presence, выход, reconnect, detached и каталог; ряд проверок читает технический `#playback` или видимые list items, поэтому их потребуется приспособить к раскрываемым подробностям.

В config остался исторический контекст прототипа; текущий объём определяют PRD, основные specs и архивированные завершённые changes. Это изменение не меняет playback/presence модели.

## Goals / Non-Goals

**Goals:**

- Оставить подписки, секреты и действия в прежнем extension iframe; content script получает только публичное название и геометрию.
- Разделить вычисление отображаемого состояния и DOM, чтобы рассогласованные callbacks не показывали ложное «Смотрим вместе».
- Управлять собственной частью заголовка, не теряя актуальное название страницы при SPA и выходе.

**Non-Goals:**

- Не переносить Firebase в worker или content script, не менять sync engine и правила возвращения following/detached.
- Не добавлять серверное состояние раскрытия, UI-настройки в каталог или новые разрешения расширения.
- Не разрабатывать особый overlay для fullscreen, мобильных устройств или YouTube mini-player; в fullscreen плеера панель остаётся вне полноэкранного элемента и появляется после выхода из него.

## Decisions

### 1. Компактная кнопка и раскрываемые подробности в прежнем iframe

Сохранить нижний левый угол и отступ 12 px. Свёрнутый вид — кнопка с названием в одну строку, текстовым состоянием и числом участников либо «—». Длинное название сокращается визуально, полное доступно в подробностях. Предварительные размеры: ширина до 320 px, высота свёрнутой области до 88 px при обычном масштабе; итоговая геометрия определяется содержимым и viewport, а не фиксированной высотой технической панели.

Подробности содержат полное название, пояснения состояния, список участников, копирование приглашения, существующие возврат/смену/повторы и выход. Числовую строку позиции/revision из пользовательского UI убрать; нужные проверки читают состояние через существующие тестовые extension-запросы. Выход не отделять за прокруткой, которая недоступна клавиатурой. Высоту подробностей ограничить доступной высотой окна с внутренней прокруткой.

Кнопка использует `aria-expanded`/`aria-controls`, видимый focus и доступное имя. Enter/Space переключают раскрытие, Escape сворачивает с возвратом фокуса. Новые статусы объявляются через один `aria-live=polite`; обновления позиции не вызывают объявлений. Цвет лишь дополняет текст. Фокус остаётся внутри iframe при действиях, чтобы горячие клавиши страницы не получали их.

Раскрытие хранить только в памяти session-документа. После reload начальное состояние свёрнуто; ошибки обновляют краткий статус, но не раскрывают панель и не перехватывают фокус автоматически. Неактивный host скрыт, iframe продолжает обслуживать extension-запросы. До появления действующей привязки нет ложного индикатора комнаты; подключение существующей привязки показывается сразу с её известным названием.

Альтернативы: постоянно раскрытая панель сохраняет проблему размера; UI в DOM YouTube усложняет сохранение секрета ручной ссылки. Новый React root не нужен для этого изменения: сохранить DOM-подход session и небольшие выделенные helpers.

### 2. Адресованное управление размером и заголовком

Добавить строгую схему presentation-сообщения session → content script по `tabs.sendMessage(..., { frameId: 0 })`: target, монотонная последовательность обновления, видимость, название и размер. В сообщении отсутствуют key, invitation, UID, участники и Auth. Отправитель проверяется как существующие player-control сообщения: свой extension ID, точный `session.html#target`, действующий host/target.

Session измеряет содержимое через `ResizeObserver`, сообщает изменения только при отличии размера. Content script ограничивает численные размеры viewport и допустимыми пределами. Изменение viewport приводит к повторному ограничению и измерению. Свёрнутый host уменьшается до индикатора; пустая площадь бывшей панели не ловит клики. Закрытый Shadow DOM сохраняется.

Порядковый номер и флаг завершения связывают presentation с жизненным циклом сессии: поздние результаты предыдущего render не применяются после более нового обновления или скрытия при выходе. После успешного `room-tab-release` session инвалидирует ожидающие render, отправляет очистку и снимает показ комнаты; новый bind начинает новое актуальное отображение. Ошибка release сохраняет привязку, заголовок и доступный повтор. При invalidation content script отключает наблюдатели и снимает host.

Альтернатива `window.postMessage` потребовала бы отдельной модели доверия. Существующий адресованный runtime путь уже отделяет страницу и посторонние session-документы.

### 3. Одна модель отображаемого состояния

Вынести чистое вычисление краткого статуса из transport, view, локального PlayerStatus и ошибок действий. Приоритет: ошибка комнаты/соединения → подключение или получение актуального состояния → detached → ограничение following-плеера → совместный просмотр. Ошибка операции добавляет видимый признак проблемы и пояснение в подробностях, не уничтожая сообщение об отсутствии связи. Пока view/плеер не подтверждены, использовать ожидание готовности, а не «Смотрим вместе».

Число считается актуальным только при `connected && roomReady && !roomError && !presenceError`; иначе показывать «—» и объяснение. Detached остаётся подключённым участником и входит в число по текущей модели presence. Участники сохраняют существующие номера/цвета; постоянные номера не вводятся. При offline последнее известное название комнаты остаётся, синхронизация не обещается.

Ошибка присутствия имеет отдельное текстовое пояснение в индикаторе и действие повтора в подробностях; её нельзя скрывать обычным статусом совместного просмотра.

Не определять поведение кнопок по тексту статуса. Сохранять структурированные локальный статус и ошибки, чтобы подписи и переносы не влияли на возврат или reload недоступного видео. Новые UI-переключения не вызывают `engine.intent`, reconnect или запись playback.

Альтернатива независимых строк в callbacks сохраняет риск устаревшего ready после потери связи или входа в detached.

### 4. Приглашение из действующей привязки

При `room-tab-ready` сохранить key/name в памяти session; при подтверждённом создании — использовать значения успешного bind. Строить ссылку существующим `invitationUrl` и текущим Firebase invitation origin. Не читать каталог, не сохранять удалённую запись и не создавать подписку ради копирования. При выходе сбрасывать локальные данные приглашения.

Копирование выполняется по нажатию внутри iframe. В случае отказа показывать read-only поле с выделяемой ссылкой, также внутри iframe. Результат объявляется как статус. Перед первым подтверждённым входом/созданием кнопка недоступна; при временном offline уже принятой комнаты приглашение остаётся доступным, без обещания доступности сервера.

Методика приёмки уточнена пользователем 2026-11-03: успешное копирование проверяется в обычном Chrome, обработка отказа и показ ручной ссылки — browser-тестом с искусственным отклонением `navigator.clipboard.writeText()`. В manifest уже есть `clipboardWrite`; ожидание естественного отказа не является условием завершения change. Искусственная ошибка проверяет защитную ветку UI, но не подтверждает естественный отказ или ручное копирование в обычном Chrome.

### 5. Контроллер заголовка в content script

Получать только название комнаты и держать отдельно последний исходный заголовок YouTube и собственный последний результат. Применять `[название] ` к актуальному исходному заголовку, используя строковые DOM API. Наблюдать изменения title и замену его узла в head; собственную запись распознавать и не запускать цикл. Не удалять произвольные квадратные скобки и совпадения названия из внешнего заголовка.

При новом внешнем заголовке сохранять его как новую базу; при снятии отображения восстанавливать эту базу только если текущая строка всё ещё является собственным результатом. Если YouTube уже записал другой заголовок, сохранить его. Reload создаёт новый контроллер, session восстанавливает имя из привязки. Смена общего видео не меняет имя комнаты; обычная watch → watch SPA меняет только базовую часть. Потеря связи и detached не снимают префикс.

Работа ограничена поддерживаемыми watch-маршрутами. При SPA-уходе на неподдерживаемый маршрут скрывать панель и снимать префикс, сохраняя существующую привязку; при возврате на watch в том же документе восстанавливать отображение. Полная загрузка неподдерживаемых страниц не требует нового автоподключения комнаты.

Альтернативы: однократная установка теряется при SPA; восстановление title, запомненного при входе, возвращает название прежнего ролика; безусловное удаление похожего префикса повреждает собственное название YouTube.

## Risks / Trade-offs

- [Изменения title и DOM YouTube] → наблюдать head/title, не DOM всей страницы; unit-проверки замены title, повторных записей и названий с совпадающими префиксами; обязательная live-проверка SPA. Если observer вызывает цикл или заголовок не удерживается на реальном YouTube, пересмотреть контроллер до закрытия приёмки.
- [ResizeObserver и ограничение высоты создают обратную связь] → измерять отдельный корневой элемент, ограничивать размеры с одной стороны, не отправлять одинаковые значения. Проверить 640×480, увеличение масштаба, длинные имена, ошибки и список участников.
- [Скрытый iframe остаётся живым] → скрытие после выхода обязательно сопровождается `unwatchRoom` и очисткой presentation; при сворачивании подписки сохраняются намеренно. Проверки presence и revision подтверждают отсутствие лишних эффектов.
- [Clipboard policy embedded iframe] → проверить реальное нажатие в Chrome и отказ; ручная ссылка остаётся внутри iframe. Новые permissions не требуются.
- [Название комнаты видно странице через title] → это прямое следствие P-07; передавать только название. Секреты не должны появляться даже в технических data-атрибутах или логах.
- [Размер и расположение могут мешать YouTube] → исходные размеры и нижний левый угол являются проектным предположением, а не проверенным UX. В live QA проверить обычный/theater режим, прокрутку и fullscreen; при перекрытии доступных контролов скорректировать геометрию в пределах этого design.

## Migration Plan

1. После отдельного разрешения пользователя реализовать UI и внутренние presentation-сообщения одной сборкой. Серверные данные, Rules и каталог не мигрируют; обратная совместимость внутренних сообщений не требуется по правилам проекта.
2. Проверить типы, сборку, unit/browser suites и целевые реальные сценарии; записать `verification.md` с фактическими результатами. Не считать текущие плановые документы подтверждением UI или live-поведения.
3. Для native QA использовать одинаковую cloud-сборку в двух обычных Chrome profiles, без деплоя серверных ресурсов ради UI. Сохранить обезличенные наблюдения и скриншоты без ссылок-приглашений.
4. После review и приёмки обновить пользовательские документы, синхронизировать specs и архивировать change. Откат UI возможен предыдущей сборкой без отката данных; публикация расширения отдельно.
