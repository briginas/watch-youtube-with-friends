# Design

## Context

WXT формирует манифест для обычной сборки, стендов и релиза. Аудит релиза сверяет `manifest.version` с `package.json`.

## Goals / Non-Goals

- Отличать локальные сборки по метке в Chrome и находить исходный коммит.
- Сохранить привязку релизной версии к ZIP и дескриптору backend.

## Decisions

- Добавлять метку в `version_name` после формирования манифеста WXT. Применять её к обычному расширению и QA, включая сборку с эмуляторами. Пропускать релиз и отдельные эксперименты.
- Использовать время UTC с миллисекундами, чтобы различать сборки, запущенные в одну секунду. Git используется только при сборке. При недоступности сведений метка содержит `no-git`.

## Risks / Trade-offs

`dirty` сообщает, что SHA указывает на базовый коммит, а сборка может содержать дополнительные правки. Для воспроизведения этих правок их нужно сохранить в Git.
