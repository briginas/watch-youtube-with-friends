# Spec Delta

<!-- Refinement: Ready — одобренный план; сценарии сохраняют изоляцию backend-generations. -->

## Purpose

Позволяет разработчику собрать проект из публичного checkout и оператору явно подключить собственные QA и production настройки без публикации личных данных.

## ADDED Requirements

### Requirement: Публичный checkout независим от локального развёртывания

Репозиторий SHALL содержать примеры конфигурации и самостоятельные тестовые данные. Обычная сборка и локальные проверки MUST работать без реальных Firebase проектов, локального инвентаря и credentials.

#### Scenario: Новый разработчик
- **WHEN** разработчик устанавливает зависимости в чистом checkout без локальных настроек
- **THEN** typecheck, unit-тесты и обычная сборка доступны
- **AND** сборка не подключается к production

### Requirement: Явная локальная конфигурация окружений

Cloud и release инструменты MUST читать явно выбранные локальные настройки, проверять их полноту и соответствие роли проекта. Реальные инвентарь, дескрипторы и состояния оператора MUST быть исключены из публикуемых файлов. Примеры MUST NOT автоматически становиться рабочими настройками.

#### Scenario: Настройки отсутствуют
- **WHEN** cloud или release команда вызвана без обязательных локальных параметров или файлов
- **THEN** команда завершается с понятной инструкцией настройки без deploy и без вывода credentials

#### Scenario: Собственный QA
- **WHEN** оператор выбирает собственный QA-проект и согласованное QA-поколение
- **THEN** cloud-сборка и проверки используют эти параметры без правок исходного кода
- **AND** production-проект или несовпадающая QA-роль отклоняются

#### Scenario: Повторная инициализация
- **WHEN** оператор повторяет команду создания локальных примеров
- **THEN** уже существующие локальные файлы не перезаписываются

#### Scenario: Перенос существующего развёртывания
- **WHEN** реальные настройки и снимки контрактов перенесены в локальное хранилище
- **THEN** release-сборка сохраняет прежние project IDs, поколения и контрольные суммы контрактов
- **AND** подготовка сборки не выполняет облачных операций

### Requirement: Настраиваемый публичный контакт

Hosting SHALL подставлять контакт поддержки из настроек оператора. Исходные шаблоны MUST NOT содержать личный email разработчика; недопустимые значения MUST отклоняться без HTML-инъекции.

#### Scenario: Контакт настроен
- **WHEN** оператор готовит Hosting с корректным email поддержки
- **THEN** страницы приглашения и privacy содержат этот контакт

#### Scenario: Контакт не настроен
- **WHEN** контакт отсутствует
- **THEN** шаблон сообщает, что контакт не настроен, без чужого адреса

#### Scenario: Контакт повреждён
- **WHEN** значение содержит HTML или недопустимые символы
- **THEN** подготовка отклоняется

### Requirement: Проверка публикуемого содержимого

Проект SHALL предоставлять проверку файлов и выбранной Git-истории на credentials и локальные данные. CI MUST выполнять локальные проверки без доступа к рабочим окружениям. Проверка SHALL сообщать категории и пути находок без значений секретов.

#### Scenario: Случайное добавление локального файла
- **WHEN** в публикуемые файлы попадает реальный env, приватный ключ или каталог оператора
- **THEN** проверка завершается с ошибкой и не печатает содержимое секрета

#### Scenario: Публикуемая история
- **WHEN** проверяется подготовленная main
- **THEN** сканируются все достижимые из неё версии файлов и метаданные коммитов
- **AND** локальная резервная история не включается в публикуемую ветку
