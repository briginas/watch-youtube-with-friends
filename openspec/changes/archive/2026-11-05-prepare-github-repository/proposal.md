# Proposal

## Why

Разработчик готовит исходники к первому размещению на GitHub. Сейчас release-скрипты и некоторые тесты зависят от инвентаря реального развёртывания, QA привязан к одному project ID, а документы и история содержат личные сведения. Одобрено отделение локальной конфигурации и новая публичная история с сохранением оригинальной ветки локально.

## Goals / Success Criteria

- Чистый checkout позволяет собрать расширение и выполнить локальные проверки без личных файлов и облачных credentials.
- QA и production используют явно выбранные локальные настройки; существующее локальное развёртывание остаётся пригодным для сборки.
- Публикуемая main содержит один стартовый коммит без исходной приватной истории и данных оператора.
- Примеры, документация и CI позволяют повторить настройку и проверять новые изменения.

## What Changes

- **BREAKING для операторских путей:** данные развёртывания переезжают в игнорируемую `.local/deployment/`; в Git остаются независимые примеры и тестовые fixtures.
- QA-конфигурация заменяет конкретный project ID, сохраняя проверки ролей и запрет production в QA.
- Контакт поддержки становится параметром Hosting; внутренние отчёты и исходные личные настройки сохраняются локально.
- Добавляются проверка публикуемых файлов/истории, CI и quick start.
- Оригинальная история сохраняется локально; чистая main создаётся после проверок.

## Non-goals

Публикация на GitHub или в Chrome Web Store, deploy, изменение облачных ресурсов, лицензирование и изменение протокола комнат не входят в задачу. Версия расширения остаётся прежней: новый релиз не готовится.

## Capabilities

### New Capabilities

- `deployment-configuration`: воспроизводимая настройка локальных QA/production окружений и публичных шаблонов без данных конкретного оператора.

### Modified Capabilities

Нет. Контракты `backend-generations` и изоляция окружений сохраняются.

## Impact

Cloud/release/status/rotation scripts, Hosting templates, fixtures, примеры окружения, документация, Git history и CI. Существующий `prepare-public-release` остаётся отдельным незавершённым change.

## Readiness

Ready — план и создание чистой main одобрены пользователем; зависимости проверены в коде и существующих specs.
