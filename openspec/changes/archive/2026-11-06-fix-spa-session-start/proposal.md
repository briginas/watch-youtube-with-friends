# Proposal

## Why

После перехода с главной YouTube к видео без загрузки нового документа popup зависает на «Подключаемся…» и сообщает об ошибке связи. Пользователь вынужден перезагружать каждую новую вкладку; сценарий воспроизведён в Chromium на управляемой странице с настоящим расширением.

## Goals / Success Criteria

На поддерживаемом видео popup подключается и разрешает создание комнаты независимо от того, открыт ли watch URL напрямую или через SPA-навигацию. Reload для первого подключения не нужен.

## What Changes

- Проверка возможности подключения учитывает текущую страницу вкладки после SPA-перехода.
- Проверки источника сообщений и единственность session iframe сохраняются.
- Регрессионные сценарии охватывают новые вкладки, прямой вход, повторное открытие popup и неподдерживаемую страницу.

## Non-goals

Не меняем Firebase, протокол комнаты, sync engine или разрешения расширения. Не добавляем инъекцию в документы, открытые до установки расширения. MVP из PRD не расширяется.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `room-session`: создание комнаты после перехода к видео внутри YouTube без reload.

## Impact

Background-проверка content script, браузерные тесты lifecycle, patch-сборка для ручной проверки. Поколение backend и локальные форматы сохраняются.

## Readiness

Ready — дефект воспроизведён; ожидаемое поведение и границы следуют из пользовательского сценария.
