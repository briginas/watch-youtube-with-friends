# Proposal

## Why

Прототип сохраняет только привязки открытых вкладок в текущем сеансе браузера: после закрытия комнаты нужно снова искать приглашение. Следующий шаг к MVP — сценарий P-06 из PRD: постоянный список созданных и принятых комнат в popup с возвратом к просмотру.

## What Changes

- Popup показывает локальный список комнат на любой странице, включая страницы вне YouTube; список сохраняется после перезапуска браузера.
- Успешное создание и принятие приглашения добавляют комнату один раз. Простое открытие приглашения и ошибки не создают запись.
- Нажатие открывает вкладку просмотра с актуальным состоянием комнаты либо активирует существующую; разные комнаты имеют разные вкладки.
- Новая комната получает общее неизменяемое название по исходному видео; при отсутствии названия используется «Видео <videoId>».
- **BREAKING**: metadata с названием обязательна. По решению пользователя обратная совместимость не требуется: старые форматы комнат, сообщений и локальных данных не поддерживаются, миграции не добавляются.
- Выход и закрытие вкладки сохраняют запись. «Убрать из списка» удаляет только локальную запись, без выхода из открытой комнаты и воздействия на остальных.
- По решению пользователя от 2026-11-03 пустые комнаты и приглашения не истекают автоматически. После перезапуска нет автоматического подключения к сохранённым комнатам.
- Область change — P-06 и необходимые для списка названия. Заголовок YouTube-вкладки и остальной UI P-07, явная смена видео P-08, эксплуатационная очистка и публикация расширения остаются отдельной работой.

## Capabilities

### New Capabilities

Нет: список и повторное открытие продолжают существующую capability `room-session`.

### Modified Capabilities

- `room-session`: сохранённый список комнат, повторное открытие из popup, автоматическое название и срок действия приглашений.

## Impact

`src/entrypoints/popup/`, `background.ts`, `src/session/main.ts`, `src/invitation/main.ts`, room messages/transport/validation и новый локальный repository списка; получение названия в `watch-session.content.ts`. Firebase Rules требуют неизменяемую metadata при создании; общий список комнат на сервере не появляется. Затрагиваются unit, Rules/integration и browser-проверки, README и PRD. QA-приёмка использует новые комнаты и сборки одного формата. Firebase остаётся в extension-документах; секреты не передаются странице YouTube. Новые зависимости не требуются.
