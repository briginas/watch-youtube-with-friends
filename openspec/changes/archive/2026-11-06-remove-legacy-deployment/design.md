# Design

## Context

См. proposal.md. `scripts/release/generation.mjs` допускает отсутствующий descriptor только для `legacy/0.2.0`; самый ранний сохранённый descriptor prod-v1 — 0.2.1. Текущий 0.2.6 ссылается на 0.2.5. В публичном реестре deployment записан только prod-v1; legacy присутствует в локальном инвентаре как runbook, без live-подтверждения.

## Goals / Non-Goals

Начальный descriptor проверяется теми же правилами проектов и контрактов, что и остальные. Протокол расширения, неизменяемые контракты prod-v1 и механизм ротации сохраняются. Новая версия пакета не готовится: это очистка операторских инструментов и инфраструктуры.

## Decisions

- `previous` обязателен, но допускает явное `null` только для mode new с firstRelease == releaseVersion. CLI `initial` преобразуется в new/null; неполные и лишние аргументы отклоняются. Пропуск previous не равен initial.
- При prepare initial каталог releases не должен содержать descriptors; при load начального descriptor не должно быть более ранних descriptors по числовой версии. Остальные ссылки всегда проверяются чтением настоящего descriptor. Так новый initial не маскирует продолжение истории.
- В локальном и example descriptor 0.2.1 заменить ложную legacy-ссылку на null, сохранив backend, control, Rules и SHA-256. Другие descriptors не менять. Снимки legacy и `.env.production.legacy` удалить; резервные исторические материалы не трогать.
- Тесты new/reuse начинают самостоятельную историю, затем проверяют переход на другое поколение, неправильного предшественника и целостность снимка. Имя legacy перестаёт иметь особый смысл.
- Перед удалением проекта проверить control privacy, заменить URL Store, убедиться в новом публичном URL; затем live-проверить точный project ID и отдельность QA/prod-v1/control, запросить удаление только legacy и проверить результат. Состояние `delete-requested`/`deleted` записывается только по ответу провайдера. При недоступности доступа незавершённая облачная задача остаётся открытой.

## Risks / Trade-offs

- Изменение формата первого descriptor несовместимо со старым tooling → явно обновить начальный локальный descriptor и примеры, проверить текущую release-сборку.
- Store может применять privacy URL после review → старый Hosting сохраняется до подтверждения публичного переключения.
- Удаление уничтожает старые комнаты и Auth → пользователь подтвердил отсутствие использования и удаление; точный проект проверяется перед действием. Запись состояния и исторические доказательства сохраняются.

## Migration Plan

Сначала локальные изменения и тесты, затем privacy URL и проверка публичной карточки, потом удаление legacy. Git-правки обратимы; секретные локальные файлы в Git не попадают. Текущие production и QA не развёртываются повторно.

## Readiness

Ready — технические зависимости проверены в коде и Store; удаление облака имеет явные условия и требует live-подтверждения результата.
