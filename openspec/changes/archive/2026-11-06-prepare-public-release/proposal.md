# Proposal

## Why

Сценарии прототипа и интерфейс комнаты реализованы, но расширение пока распространяется как QA unpacked-сборка. Для публичного выпуска нужны отдельное серверное окружение, проверенный пакет и полноценный путь установки через Chrome Web Store — без расширения объёма MVP из PRD.

## What Changes

- Подготовить отдельный production Firebase-проект с Anonymous Auth, RTDB и Hosting; QA-проект `example-qa` сохранить для проверок. Решение пользователя от 2026-11-04.
- Добавить отдельную release-конфигурацию и сборку версии `0.1.0`: manifest, иконки, ZIP с `manifest.json` в корне, контроль состава и SHA-256. Release-команда не должна молча брать настройки QA или эмуляторов.
- Проверять пакет на приватные ключи, статические токены, секреты тестовых комнат, файлы окружения и диагностические инструменты; публичные настройки Firebase учитывать отдельно от секретов. Проверка относится к поставляемому пакету, а не только к исходникам.
- Подготовить страницу privacy policy, сведения о поддержке, описание, обоснования разрешений, disclosures, реальные screenshots и инструкцию для проверяющего Chrome Web Store. Издатель: `briginas`, публичный контакт: `support@example.invalid`.
- Обновить публичную страницу приглашения: установка из Chrome Web Store, сохранение существующего сценария входа и доступ к privacy policy. Фактический store ID появляется после первого создания draft item.
- Зафиксировать эксплуатационные параметры, мониторинг потребления, ограничения публичного клиента, порядок деплоя, восстановления и публикации. Сначала загрузить draft и получить store ID, после review публиковать согласованно со страницей приглашения.
- Успех подготовки пакета, деплоя, подачи на review и фактической публикации учитывать раздельно. Переход сразу к подготовке выпуска не считается выполнением ранее предложенных диагностик и приёмки на разных сетях.

## Capabilities

### New Capabilities

- `extension-distribution`: проверяемый публичный пакет, разделение окружений и публичные сведения о данных и установке.

### Modified Capabilities

Нет. Существующее требование `room-session` уже предусматривает инструкцию установки при отсутствии расширения. Его уточняет новый контракт распространения, без изменения протокола входа, общего playback и срока жизни комнат.

## Impact

- `package.json`, release scripts, `wxt.config.ts`, публичные иконки, `.env.example`/образец release-конфигурации, документация сборки.
- `scripts/cloud.mjs` и общий генератор облачных настроек при необходимости выделения переиспользуемой части; `firebase.json`, `firebase/hosting/`, будущие release-проверки.
- Отдельный Firebase-проект и существующий Chrome Web Store developer account `operator@example.invalid`: пользователь подтвердил аккаунт и выбрал его для выпуска 2026-11-04; dashboard открыт в браузере по сообщению пользователя. Email аккаунта не подставляется вместо публичного контакта поддержки `support@example.invalid`. Платёжные параметры и окончательный запуск требуют реальных данных владельца; их значения не выдумываются.
- PRD/ADR и эксплуатационная документация уточняются по выполненным работам. Схема комнат, бессрочные приглашения и локальность личных настроек сохраняются; миграция QA-данных не планируется.
- Реализация, создание ресурсов, деплой и отправка в store ещё не выполнены. Первичная проверка текущего QA-пакета: [package-audit.md](package-audit.md).
