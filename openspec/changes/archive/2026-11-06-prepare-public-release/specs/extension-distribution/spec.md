# extension-distribution Spec Delta

## Purpose

Определяет состав публичного расширения, изоляцию серверного окружения и доступные пользователю сведения об установке и обработке данных при распространении через Chrome Web Store.

## ADDED Requirements

### Requirement: Отдельное публичное окружение

Публичная сборка MUST использовать явно выбранное production-окружение, отдельное от QA и эмуляторов. При отсутствии полной production-конфигурации выпуск пакета MUST завершаться ошибкой без подстановки QA-настроек.

#### Scenario: Настроенный production

- **WHEN** создаётся публичный пакет с полной production-конфигурацией
- **THEN** серверные подключения и приглашения относятся только к выбранному production-окружению
- **AND** QA-комнаты и их секреты не включены в пакет

#### Scenario: Неполная или тестовая конфигурация

- **WHEN** release-команда получает неполные настройки, эмуляторный флаг или известный QA-проект
- **THEN** пакет для публикации не выпускается, а сообщение указывает причину без вывода чувствительных значений

### Requirement: Проверяемый пакет расширения

Публичный пакет SHALL быть ZIP-архивом с manifest в корне, согласованной версией, описанием и PNG-иконками. Пакет MUST содержать только файлы расширения и сопровождаться контрольной суммой, позволяющей установить, какой пакет проверен и загружен.

#### Scenario: Выпуск архива

- **WHEN** release-сборка и проверка её состава успешно завершены
- **THEN** созданный ZIP содержит `manifest.json` в корне и все перечисленные в manifest ресурсы
- **AND** рядом доступны версия и SHA-256 самого ZIP

### Requirement: Отсутствие встроенных приватных данных

Поставляемый пакет MUST NOT содержать приватные ключи, service-account credentials, статические Auth-токены, секреты тестовых комнат, файлы окружения или QA-инструменты. Публичные настройки Firebase SHALL учитываться отдельно и не считаться средством авторизации.

#### Scenario: Обнаружена чувствительная информация

- **WHEN** проверка готового пакета обнаруживает запрещённые файлы или известные чувствительные значения
- **THEN** выпуск останавливается до их удаления
- **AND** отчёт содержит тип находки и имя файла без самого секрета

#### Scenario: Публичная конфигурация клиента

- **WHEN** пакет содержит Web API key, project ID и публичные URL production Firebase
- **THEN** они перечислены в отчёте как публичная конфигурация без вывода API key
- **AND** доступ к данным по-прежнему требует Auth и действующих серверных Rules

### Requirement: Сведения об обработке данных

Публичный сайт SHALL предоставлять доступную без расширения и авторизации privacy policy с издателем, контактом, назначением передаваемых данных, получателями и фактическими сроками хранения. Сведения в Chrome Web Store MUST соответствовать поведению поставляемой версии.

#### Scenario: Чтение политики

- **WHEN** пользователь открывает privacy policy без расширения
- **THEN** он видит издателя `briginas`, контакт `support@example.invalid`, сведения об Anonymous Auth, состоянии комнаты, presence и локальном каталоге
- **AND** выход и удаление из списка не описаны как удаление серверной комнаты

### Requirement: Установка по публичному приглашению

После публикации расширения страница приглашения SHALL предлагать установку из действующей карточки Chrome Web Store и возврат к приглашению после установки. До доступности карточки сайт MUST NOT утверждать, что расширение уже опубликовано. Ссылка на privacy policy SHALL быть доступна при любом состоянии установки.

#### Scenario: Расширение отсутствует после публикации

- **WHEN** пользователь открывает приглашение без установленного расширения
- **THEN** видит ссылку на фактическую карточку расширения и указание вернуться и обновить страницу после установки
- **AND** секрет приглашения не передаётся в URL карточки или privacy policy

#### Scenario: Карточка ещё недоступна

- **WHEN** подготовленный сайт развёрнут до публичной доступности расширения
- **THEN** он явно сообщает, что публикация ожидается, без ложного подтверждения установки или входа

#### Scenario: Расширение уже установлено

- **WHEN** пользователь открывает действительное приглашение с установленной release-версией
- **THEN** сохраняется существующий явный вход через «Присоединиться»
- **AND** просмотр privacy policy не требует входа в комнату
