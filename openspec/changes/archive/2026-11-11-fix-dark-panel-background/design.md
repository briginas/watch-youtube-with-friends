# Design

## Context

См. proposal.md. `appearance.css` задаёт корню тёмный `color-scheme`; iframe в `watch-session.content.ts` использует `normal`. Прозрачного background в `session/style.css` недостаточно: [CSS Color Adjustment](https://www.w3.org/TR/css-color-adjust-1/Overview.html) требует непрозрачный canvas при несовпадении схем iframe и корня документа.

## Goals / Non-Goals

**Goals:** согласовать схемы canvas, сохранив общие CSS-переменные и тёмные нативные контролы внутри панели.

**Non-Goals:** изменение обмена сообщениями, хранения темы и палитры popup.

## Decisions

Явно задать light у iframe и корня session в обеих темах. Для body тёмной панели вернуть dark: это сохраняет вид scrollbar и input без влияния на canvas. Правка ограничена session; общая палитра остаётся прежней. Альтернатива с передачей темы в content script добавляет ненужную синхронизацию и промежуточные состояния.

Проверка: дополнить существующий браузерный сценарий темы чтением пикселей screenshot страницы в скруглённом углу и промежутке панели. Одного computed background недостаточно: он уже transparent при ошибке. Проверить обе темы страницы, свёрнутое/раскрытое состояние, возврат к светлой теме и reload с сохранённой тёмной.

## Risks / Trade-offs

[Различия отрисовки браузеров] → проверить в Chromium с настоящим extension iframe; видеостенд подтверждает композицию UI, но не является live-проверкой YouTube.

## Readiness

Ready — причина описана спецификацией CSS и совпадает с кодом; локальное исправление обратимо и проверяется снимками браузера.
