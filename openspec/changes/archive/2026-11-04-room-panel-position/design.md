# Design

## Context

Мотивация и границы: [proposal.md](proposal.md). Панель — extension iframe внутри закрытого Shadow DOM; host добавляется в `document.documentElement` и закреплён внизу слева. `renderPresentation()` учитывает привязку и watch-маршрут, но не fullscreen. Обработчиков перетаскивания нет. Существующая проверка обычного fullscreen не покрывает случай, когда полноэкранным становится корневой элемент вместе с host. Конкретный способ входа пользователя в fullscreen пока не воспроизведён.

## Goals / Non-Goals

**Goals:** явное скрытие независимо от fullscreen-элемента, плавное перемещение через границу iframe, сохранение короткого клика и доступности панели.

**Non-Goals:** сохранение позиции между reload/устройствами, размещение панели внутри fullscreen, изменение transport/engine и серверных данных.

## Decisions

1. Разделить доступность сессии и видимость панели. `fullscreenchange` обновляет только видимость; префикс title зависит от действующей watch-сессии, а не fullscreen. Дополнительно проверять признаки fullscreen самого YouTube в существующем цикле проверки маршрута, обновляя DOM только при смене состояния. Полагаться на z-index и расположение вне плеера недостаточно: полноэкранный root может содержать host.
2. Обрабатывать Pointer Events на существующем заголовке `#room-toggle`, добавив курсор захвата. Небольшой порог движения отличает drag от клика. Захват pointer сохраняет жест за пределами iframe; после drag подавляется только связанный с ним click. Enter/Space/Escape продолжают работать. Завершать жест при pointerup/cancel, потере захвата или фокуса и скрытии панели.
3. Session-документ передаёт только события геометрии через `postMessage`; parent принимает их по совпадению `source` с текущим iframe, extension origin, target и строгой схеме. В обратную сторону передаётся только отмена жеста с публичным target; секреты комнаты не передаются. Проверять устаревшие жесты; после скрытия/смены target перемещение прекращается. Координаты движения считать относительно начала жеста по screen-координатам: client-координаты меняются при движении самого iframe и могут вызвать дрожание. Альтернатива с runtime-сообщением на каждый pointermove добавляет асинхронные переходы в цепочку отрисовки.
4. Геометрию host хранить в content script текущего документа. До первого drag остаётся привязка внизу слева; после — положение относительно viewport. При новом размере панели или окна координаты ограничиваются доступной областью. На маленьком окне высота по-прежнему ограничена, подробности прокручиваются. SPA в том же документе сохраняет положение; reload сбрасывает его. Это осознанное допущение плана без нового формата storage.

## Risks / Trade-offs

- Перемещение cross-origin iframe может влиять на доставку мыши → browser-проверки настоящих pointer events и отдельное наблюдение на реальном YouTube; стенд не подтверждает поведение YouTube.
- Fullscreen YouTube может отличаться по платформам → проверить fullscreen плеера и root на стенде, штатный fullscreen YouTube отдельно; записать способ входа и версию браузера. Если пользовательский вариант не воспроизводится, сохранить ограничение в отчёте.
- Отмена drag может оставить подавление следующего клика → проверить отмену, потерю фокуса и последующий обычный клик/клавиатуру.
- Раскрытие панели в нижнем углу может вытолкнуть действия из окна → пересчитывать ограничение координат после изменения размера и проверять доступность выхода при 640×480.
- Новое сообщение геометрии не должно ослабить изоляцию → тест отказа для page/postороннего iframe, неверного target и устаревшего жеста.

## Migration Plan

Изменения только в расширении; после реализации нужна свежая сборка и перезагрузка watch-вкладок для обновления content script. Firebase не требует деплоя. Откат — предыдущая сборка и reload вкладок.
